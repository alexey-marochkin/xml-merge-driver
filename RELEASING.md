# Выпуск версий

Выпуск запускается при отправке в GitHub тега вида `vМАЖОР.МИНОР.ПАТЧ`, например `v0.2.0`. Тег должен указывать на проверенный коммит с файлом `.github/workflows/release.yml`. Сначала отправьте коммит в `main`, затем создайте и отправьте тег:

```sh
git push origin main
git tag -a v0.2.0 -m "XML Merge v0.2.0"
git push origin v0.2.0
```

GitHub Actions проверяет точный формат тега и выполняет тесты на Windows и Linux. После успешной сборки обоих комплектов он публикует один [GitHub Release](https://github.com/alexey-marochkin/xml-merge-driver/releases) с файлами `XmlMerge-Windows-x64-<версия>.zip`, `XmlMerge-Linux-x64-<версия>.tar.gz` и контрольными суммами `SHA256SUMS.txt`. Windows-комплект содержит собственное окно WebView2; Linux-комплект открывает тот же интерфейс в браузере. Оба содержат готовые `rules.xml` и `merge-policy.xml`.

Если тест или сборка любой системы не прошли, релиз не публикуется. Исправьте проблему в новом коммите и создайте **новый** тег версии. Не переносите опубликованные теги на другие коммиты. Предыдущий выпуск `v0.1.0` сделан вручную; дальнейшие теги обрабатывает workflow.
